# State of the art and inspiration brief: household simulator + explorable data app

Researched 24 Oct 2026. Convention: no mark = read at the source; (~) = secondary source or recalled, verify before relying on it. Official pages for IFS and the DSFR site returned 403 to us; DSFR terms were read via its GitHub repo.

## 1. Household tax-benefit simulators

**PolicyEngine (UK/US), the one to study.** Open source (AGPL), based on OpenFisca. [Repo](https://github.com/PolicyEngine/policyengine-app-v2).
- Household report = headline net-income change, then a *net-income breakdown tree*, then "earnings variation" and *marginal tax rate* charts (PR [#1339](https://github.com/PolicyEngine/policyengine-app-v2/pull/1339)). Steal the pair "tree of components + curve over the whole earnings range". Their reform side adds decile, winners/losers, poverty and inequality views (~).
- Two sister projects are near-analogues of our app. [UK Autumn Budget dashboard](https://github.com/PolicyEngine/uk-autumn-budget-dashboard-2026): Python microsim run offline, front end (Next.js, Recharts) only reads pre-computed CSV, **shareable URLs encode the policy configuration**, and a *disclosure-control step* fails the build if a published file isn't on a sha256-reviewed list. [OBBBA Household Explorer](https://github.com/PolicyEngine/obbba-household-by-household): SvelteKit, deep links via `?household=`, a manifest recording model versions and headline checks, Vitest + Playwright. Steal: build-time manifest of versions plus "headline checks", and a build gate on what ships.
- Their bugs are free test cases: a hover breakdown disagreeing with the headline ([issue #252](https://github.com/PolicyEngine/obbba-household-by-household/issues/252)); the household route is differential-tested against the national route (12 households, 9,917 figures equal, [PR #42](https://github.com/PolicyEngine/uk-autumn-budget-dashboard-2026/pull/42)). Steal: *components must sum to the headline*, and two code paths must agree.

**OpenFisca-France / LexImpact.** [OpenFisca-France](https://github.com/openfisca/openfisca-france) (AGPL) encodes law as variables plus dated parameters, with [YAML tests](https://openfisca.org/doc/coding-the-legislation/writing_yaml_tests.html) (`name / period / absolute_error_margin / input / output`). LexImpact (Assemblée nationale) runs *cas types* and whole-population results side by side, compares "status quo / government / my amendment", and explicitly keeps AI out of the core computation because outputs vary ([summary](https://modparl.substack.com/p/leximpact)). Steal: cas types as first-class objects; test-file format; no LLM in the calculation path.

**mes-aides / 1jeune1solution.** [aides-jeunes](https://github.com/betagouv/aides-jeunes) (AGPL): Vue front, Node, MongoDB, OpenFisca server; one URL per question step; a `debug=parcours` mode lists every step; simulation data purged after 31 days. Steal: step-per-URL (back button works) and a "show all steps" QA mode. Lesson: users still report wrong results from the official multi-benefit portal and get "à titre indicatif" back ([example](https://www.plus.transformation.gouv.fr/experiences/3245838_simulateur-pas-fiable)). A disclaimer alone does not buy trust.

**mon-entreprise / Publicodes.** [Publicodes](https://publi.codes/) (MIT) is a YAML-like rules language whose JS interpreter runs in the browser and **auto-generates explanations of each result**; also behind [Nos Gestes Climat](https://nosgestesclimat.fr/en/modele), which computes in-browser on purpose because answers are too revealing to store. Steal: the explanation tree generated from the rules (we hand-build the same output in TS, section 3) and the privacy rationale.

**IPP: TAXIPP and Barèmes IPP.** [TAXIPP](https://www.ipp.eu/en/tools/taxipp-micro-simulation/) is open and linked to OpenFisca. [Barèmes IPP](https://www.ipp.eu/en/tools/baremes-ipp/) holds French legal parameters back to 1914 (open licence, attribution required). An INSEE study of [marginal rates](https://www.insee.fr/fr/statistiques/3652165) (Jan 2019, TAXIPP on 2011 data, single employee) shows the "tilde"-shaped curve peaking near 80%: +1 € of pay costs 27 c of housing allowance, 30 c of other benefits, 21 c of contributions. Steal: that exact decomposition as the explanatory device of the MTR chart, recomputed on current law.

**IFS (UK).** [What are the parties' plans for benefits and taxes?](https://ifs.org.uk/calculators/what-are-parties-plans-benefits-and-taxes) (June 2024): effect by income decile and by family type, toggle cash vs % of income, only manifesto policies plus already-legislated changes, with the unmodelled stuff stated. Steal: the € / % toggle and an explicit "modelled / not modelled" list.

**Others.** Tax Policy Center's 2016 candidate calculator needed three inputs (income, marital status, children) (~, [Fox Business](https://foxbusiness.com/politics/tax-calculator-based-on-presidential-candidate-plans)): the floor for an express mode.  Dan Neidle's [marginal-rate chart](https://taxpolicy.org.uk/2024/03/10/infographic_marginal_rates_2024/) toggles components via the legend, with assumptions listed and the Python on GitHub. The Atlanta Fed [cliff explainer](https://www.atlantafed.org/what-we-study/workforce-development/advancing-careers-for-low-income-families/what-are-benefits-cliffs) plots net resources vs earnings. ASPE's [eMTR lessons](https://digitalgovernmenthub.org/library/helping-people-with-low-incomes-navigate-benefit-cliffs-lessons-learned-deploying-a-marginal-tax-rate-calculator/): the hard part is keeping parameters current, not the UI.  The Observatoire des inégalités' [salary-rank tool](https://www.inegalites.fr/Outils) (reported 3M+ uses, ~) proves French appetite for "où me situer" single-input tools.

**Cautionary tale.** In 2024 the government's pension simulator against the NFP programme (maretraitenupes.fr) was taken to court by LFI for "simulateur mensonger" because it relied on an amendment not in the programme; it was renamed ([MoneyVox](https://www.moneyvox.fr/retraite/actualites/98484/les-macronistes-changent-le-nom-un-simulateur-de-retraites-attaque-par-lfi)). A partisan simulator is judged on its assumptions, so ours must publish them, tied to book pages. Note the site's own promise ("vous rendre 600 € par mois") will be tested household by household.

**Patterns to adopt.**
- *Form:* express mode of about 5 fields, then optional "Affiner". Benefits (RSA, prime d'activité, APL, AF) should be **computed from the situation, not typed**, with an "à corriger : je perçois en réalité X" override, because users rarely know them and a baseline that disagrees with their CAF notice kills trust.
- *Result:* one sentence ("Selon nos hypothèses, vous gagneriez/perdriez X €/mois"), waterfall before→after, per-measure attribution (state the ordering convention, as OBBBA does), curve, "people like you".
- *Trust:* every line expands to formula, parameter, Légifrance link; version stamp; open repo; published gap table versus official simulators.

## 2. Data-viz and explorable-explanation exemplars

- **[Our World in Data Grapher](https://ourworldindata.org/redesigning-our-interactive-data-visualizations):** chart/map/table tabs, source always visible with "learn more", CSV/PNG/SVG download, links whose preview thumbnail shows the exact configuration. Copy the patterns, **not the code**: the repo is now "no reuse without written permission" ([README](https://github.com/owid/owid-grapher)).
- **The Pudding / scrollytelling:** start with a question, go big-to-small ([course notes](https://knightcenter.utexas.edu/JC/courses/DATA0819/Eng/Data-stories.pdf), ~); a common pattern is a guided scrolly first, then free exploration. [Scrollama](https://github.com/russellsamora/scrollama) (MIT, IntersectionObserver, v3.2): use pixel offsets on mobile, avoid `vh`.
- **NYT "You Draw It":** predict, then reveal. A [study](https://arxiv.org/html/2401.05511v1) found drawing a guess raised surprise and engagement but not attitude change. Use it for 3 or 4 key numbers ("combien l'État dépense-t-il par jour et par habitant ?"). WCAG 2.2 SC 2.5.7 requires a non-drag alternative: add a numeric field.
- **Bret Victor, [Explorable Explanations](http://worrydream.com/ExplorableExplanations/):** his 2024 postscript says the original idea was a persuasive argument backed by a *visible, editable model* that rivals can rebut by changing it. That is the right framing for an opinionated book: expose assumption sliders.
- **"Where does my money go" family:** the White House [Taxpayer Receipt](https://obamawhitehouse.archives.gov/blog/2011/04/15/your-taxpayer-receipt) (pick an income level, no data entry) and the Google/Eyebeam [Data Viz Challenge](https://developers.googleblog.com/en/happy-tax-day-now-where-did-your-tax-dollars-go/) entries ("minutes/days worked to cover public spending", "What do you work for?"). French base data: Bercy's "pour 1 000 €" breakdown ([info.gouv](https://www.info.gouv.fr/index.php/actualite/impots-comment-fonctionne-le-systeme-fiscal-francais)); protection sociale is about 561 or 567 € depending on the source, so pin one source and year.
- **Peers:** France 57.1% of GDP in 2024 vs euro area 49.6%, EU 49.2%, Finland 57.6% ([summary](https://www.journaldunet.com/business/1545523-depenses-et-dette-publique-la-position-de-la-france-face-au-reste-de-l-europe/), Eurostat COFOG underlies it; [DREES comparisons](https://drees.solidarites-sante.gouv.fr/communique-de-presse-jeux-de-donnees/jeux-de-donnees/comparaisons-des-depenses-publiques-en-france)). Strongest idea: **convert the peer gap to a per-household, per-month figure**, which links the dashboard to the simulator.
- **Datawrapper [accessibility practice](https://www.datawrapper.de/academy/how-we-make-sure-our-charts-maps-and-tables-are-accessible):** keyboard chart explorer, "Get the data" link, alt text, colour-blind checker, contrast-aware labels, rem-based text.
- **Maps:** [gregoiredavid/france-geojson](https://github.com/gregoiredavid/france-geojson) (Etalab licence, IGN Admin Express 2018, simplified and `avec-outre-mer` variants). Choropleth rates or per-capita values only; consider a tile-grid so Paris and Corsica stay visible.
- **Reframing menu:** per inhabitant, household, day, hour worked, per 100 € of your own pay, a "jours travaillés pour l'État" calendar. One canonical definition per figure; show the arithmetic.

## 3. Technical stack (2025-2026)

- **Framework:** [Astro 6](https://astro.build/blog/joining-cloudflare/) is stable (2026); Cloudflare bought the team in Jan 2026 but it stays MIT, multi-host. Islands = zero JS on prose pages, strong SEO. SvelteKit + `adapter-static` is the credible alternative for an app-like site (PolicyEngine's OBBBA explorer uses it; [LayerCake](https://layercake.graphics/) renders charts server-side). Next.js static export works but brings the most machinery for a no-backend site. A plain Vite+React SPA is weakest for SEO.
- **Charts:** Observable Plot (ISC) for most charts, d3 modules (scale, shape, geo, format) for waterfall, MTR curve and map. Avoid ECharts (about 150-170 kB gz in a [TanStack comparison](https://tanstack.com/charts/latest/docs/comparison)) and Plotly (PolicyEngine pays that cost). Vendor size claims conflict; measure your own build. Every chart ships a static `<figure>` with text summary and data table.
- **Maps:** pre-project the simplified GeoJSON at build time (`geoConicConformal`, parallels 44/49, DROM insets) into static SVG paths. d3-composite-projections looks legacy (Travis CI era), so don't depend on it.
- **Rules encoding:** pure functions `(household, params) → trace`, no I/O, no `Date.now()`. Params are dated JSON validated by Zod, each value carrying `source_url` and `valid_from` (OpenFisca/Barèmes IPP model). A reform is a parameter patch plus optional rule module. Output is a **trace tree** (label, formula, inputs, value, source) that powers the waterfall and "voir le calcul". Hand-written TS rather than Publicodes: fewer moving parts for agents and CI; revisit if rules exceed about 150.
- **Licensing:** OpenFisca-France is AGPL: don't copy its code or parameter files; write from legal text and Barèmes IPP, use OpenFisca only as an offline oracle. Choose our own licence deliberately (open source is a trust signal).
- **URL state:** put it in the **hash**, not the query string (hashes never reach servers or CDN logs): `#v1.<base64url(compact JSON)>`, Zod-validated on load, versioned so old links still decode. "Copier le lien" warns that it contains the situation.
- **Privacy:** compute client-side, zero third-party requests, self-host fonts, strict CSP. If analytics are wanted, use cookieless, self-hosted, aggregate-only; CNIL reportedly no longer publishes a list of exempt tools since 2026-01-01 so the publisher must self-justify (~, [Matomo guide](https://matomo.org/faq/how-do-i-configure-matomo-without-tracking-consent-for-french-visitors-cnil-exemption/)). Never log inputs.
- **Accessibility:** legal reference RGAA 4.1.2 (WCAG 2.1 AA); RGAA 5 (WCAG 2.2) announced for end 2026 (~). Target WCAG 2.2 AA anyway: 2.5.7 (no drag-only), 2.5.8 (24 px targets), 3.3.7 (no redundant entry), 2.4.11 (focus not hidden). Legal obligation for us is doubtful (not a public body); publish a voluntary déclaration d'accessibilité.
- **French formatting (verified in Node 22):** `Intl.NumberFormat('fr-FR')` emits U+202F (narrow no-break) for thousands and U+00A0 before `€` and `%` ("1 234 567 €", "57,1 %", compact "3,2 Md"). Centralise in one `fmt.ts`; use `type="text" inputmode="decimal"` and a tolerant parser (accept "1 234,5", "1234.5"); check your font has U+202F; test with exact code points.
- **DSFR: do not use it.** Its terms say it must not be used by entities outside the administration; Art. 14 limits use to `.gouv.fr` sites and apps; Art. 8 warns that use outside the framework "est susceptible de créer une confusion avec un service public officiel"; Marianne fonts carry separate conditions ([CGU](https://raw.githubusercontent.com/GouvernementFR/dsfr/main/doc/legal/cgu.md), [README](https://github.com/GouvernementFR/dsfr)). For a book that criticises the State, looking official is a credibility and legal liability. Borrow *patterns* only (stepper, error messages, required-field convention, skip links) and build your own tokens.

## 4. QA and agent orchestration

- **Golden cases:** OpenFisca-style files (`name, period, input, output, tolerance`). Seed from three oracles: OpenFisca-France run offline; the DGFiP income-tax source ([Mlang](https://repos.ecosystem.code.gouv.fr/hosts/gitlab.adullact.net/repositories/dgfip%2Fimpots-nationaux-revenu-patrimoine-particuliers%2FMlang), GPL, use outputs only); about 30 hand-verified runs on caf.fr / impots.gouv. Publish the resulting gap table. Context: CNAF and Inria are adopting [Catala](https://caf.fr/professionnels/presse/publications/la-cnaf-et-inria-s-engagent-ensemble-pour-developper-catala-une-solution-souveraine-de-calcul-des) for benefit rules, so law-as-code is state practice.
- **Property tests** ([`@fast-check/vitest`](https://fast-check.dev/docs/tutorials/setting-up-your-test-environment/property-based-testing-with-vitest/)): (1) net income never decreases when gross rises, except whitelisted thresholds, and no single-euro step loses more than a set cliff budget; (2) a reform with unchanged params gives Δ = 0 exactly; (3) waterfall components sum to the headline; (4) benefits ≥ 0, vanish at high income, family benefits non-decreasing in children; (5) swapping adults' order changes nothing; (6) URL-state round-trip; (7) simulator equals the pre-computed dashboard grid. Fixed seed in CI, 10,000 runs nightly; feed shrunk counterexamples to agents as bug reports.
- **Number provenance:** every public figure lives in `facts.json` (value, unit, year, source URL, book page) and prose uses templates; CI fails on hard-coded numbers or missing sources. A second "auditor" agent re-derives 10% of them each release.
- **Persona agents:** 10 personas (SMIC solo renter; single mother 2 children on RSA + prime d'activité; dual-income cadres; retired; student on APL; auto-entrepreneur; fonctionnaire; 3-child family in a high-rent zone; DOM resident; screen-reader user; 360 px phone). LLM agents driving Playwright with think-aloud find breakages and confusing copy, but research ([UXAgent](https://arxiv.org/pdf/2504.09407), [vizron](https://ceur-ws.org/Vol-4249/paper5.pdf)) says their behaviour is not realistic and biased: never treat them as validation. Follow with 5 real people.
- **Gates in CI:** tsc strict; Vitest; Playwright E2E; `@axe-core/playwright` (0 serious/critical); Lighthouse CI budgets (mobile Perf ≥ 95, A11y 100, LCP < 2.5 s, JS budget per page); a Playwright test that **fails on any non-same-origin request**; link checker. Playwright's own docs say automated checks do not find all WCAG violations, so add a manual pass: keyboard-only, NVDA/VoiceOver, 320 px reflow, 200% zoom, reduced-motion, forced-colours.

## 5. Recommendations for our app

**Top 15 ideas, ranked**
1. Pure-TS engine + dated, sourced JSON parameters; reforms are parameter patches.
2. Express form (about 5 fields, instant result), "Affiner" optional; compute benefits, let users override.
3. Result = one honest sentence + before→after waterfall with per-measure attribution + expandable "voir le calcul" (formula, parameter, Légifrance link).
4. Visible hypotheses register (H1…Hn, each linked to a book page) and a "modelled / not modelled" list on the result screen.
5. Show losers as well as winners: cas-type heatmap (income × family type) precomputed, INSEE-decile placement, € / % toggle (IFS, LexImpact, Observatoire).
6. Net-vs-gross curve with MTR decomposition, before vs after, user marker, cliffs flagged (PolicyEngine, INSEE tilde).
7. Golden tests from three oracles + published gap table.
8. Property-based invariants (cliff budget, identity reform, sum rule).
9. 100% client-side; versioned state in URL hash; CI test forbidding third-party requests.
10. `facts.json` single source of truth for all public numbers, with source and year.
11. Reframing library (per inhabitant/household/day/hour, "ma part" receipt) and the EU-peer gap converted to € per household per month.
12. Predict-then-reveal on 3 or 4 headline numbers, with numeric-input alternative.
13. Dashboard = short scrolly story, then OWID-style chart/map/table tabs with source overlay, CSV/PNG download, link previews.
14. Accessibility by construction: per-chart text summary + data table + direct labels + colour-blind-safe palette + reduced motion; WCAG 2.2 AA.
15. Own visual identity (not DSFR), persona-agent plus human tests, Lighthouse/axe gates.

**Recommended stack.** Astro 6 (static, content collections, MDX) + React 19 islands (`client:load` for the simulator, `client:visible` for charts). Why React over Svelte: AI agents write it most reliably, and accessible primitives (React Aria Components or Radix) exist; swap to SvelteKit if a Svelte-fluent human will own it. pnpm monorepo: `packages/engine` (pure TS + Zod), `packages/params`, `packages/facts`, `apps/web`. Observable Plot + d3 modules, build-time SVG maps from france-geojson. Vitest + fast-check, Playwright + axe, Lighthouse CI. Static host (Cloudflare Pages, Netlify or GitHub Pages) with strict CSP, self-hosted fonts, no analytics at launch.

**Anti-patterns**
- Asking users to type benefits they don't know; `type="number"` inputs; a 20-field wall.
- False precision ("+312,47 €"): round to 5 or 10 €/month and state the range.
- Assumptions buried in a footer or PDF; "vous gagnerez" instead of "selon nos hypothèses" (the maretraitenupes lesson).
- Cherry-picked cas types or showing only winners.
- Any backend, tracker, third-party font, or LLM in the calculation path.
- DSFR, Marianne, blue-white-red, or `.gouv` styling.
- Hover-only tooltips, rainbow palettes, dual axes, 3D, many-slice pies, choropleths of raw totals, scroll-jacking, animation ignoring `prefers-reduced-motion`.
- Copying OWID Grapher or AGPL code without a licence decision; OpenFisca-France in the browser via Pyodide (unproven, heavy).
- Hard-coded numbers in components; unsourced statistics; mixing years or sources for the same figure.
- Modelling everything: cover the ten or so mechanisms the reforms touch; document the rest as out of scope.
